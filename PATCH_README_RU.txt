СЛАДКИЙ ЗАБЕГ — TASK HUB UI, ЭТАП 4: ФИЛЬТРЫ, БЕЙДЖИ, СОРТИРОВКА И ПРОГРЕСС
Дата: 2026-09-30

Что сделано
===========

1. Фильтры Task Hub
   - Все
   - Ежедневные
   - События
   - Цепочки
   - 🎁 Готово N — появляется только когда есть готовые к получению награды.

   Фильтрация выполняется на уже загруженном /api/tasks/state. Новых API-запросов
   при переключении фильтров нет.

2. Нормальные статусные бейджи карточек
   На карточке показывается один главный бейдж, а не набор конкурирующих меток:
   - ПРОВЕРКА ВЫДАЧИ
   - ГОТОВО ✨ / ГОТОВО 🎁
   - ПОЛУЧЕНО
   - СКОРО ЗАКОНЧИТСЯ
   - ЕЖЕДНЕВНОЕ / СОБЫТИЕ / ЦЕПОЧКА / ОДНОРАЗОВОЕ как fallback.

   Тип задания и оставшееся время дополнительно остаются в спокойной текстовой
   строке под описанием, поэтому контекст не теряется даже при статусном бейдже.

3. Приоритет состояний
   UI использует единый приоритет:
   - незавершённая/повторная проверка выдачи;
   - новая готовая награда;
   - готовая награда;
   - скоро заканчивается (<= 3 часов);
   - обычное активное состояние;
   - полученные задания уходят вниз списка.

4. Автоматическая сортировка
   Сверху автоматически оказываются задания, требующие внимания:
   - проверка выдачи;
   - новые готовые;
   - остальные готовые;
   - скоро заканчивающиеся;
   - активные по убыванию прогресса;
   - полученные.

   Внутри одинакового приоритета сохраняется исходный серверный порядок.
   Для заканчивающихся целей раньше заканчивающееся задание идёт выше.

5. Улучшенный прогресс
   Worker теперь отдаёт triggerType как presentation metadata. Сам прогресс и
   выполнение по-прежнему считаются только на сервере.

   Task Hub показывает понятные подписи по типу условия, например:
   - 2 / 3 забега
   - 1 430 / 2 000 очков
   - Лучший забег: 1 760 / 2 000 очков
   - 24 / 30 зефирок
   - 4 / 5 кофе
   - 3:42 / 5:00
   - Этап 3 из 5

6. Мобильный UX
   Фильтры сделаны горизонтальными chips со скроллом, чтобы не сжимать пять
   кнопок в узкую сетку Telegram Mini App. Для маленьких экранов уменьшен
   максимальный размер длинного статусного бейджа.

Архитектура / безопасность
==========================

- Claim, награды, прогресс, read/unread и сортируемые статусы не перенесены на
  клиент как источник истины.
- Клиент лишь форматирует уже authoritative состояние.
- Единственное расширение API — безопасное поле triggerType для корректной
  подписи прогресса.
- Новых startup/API запросов нет.
- Схема D1 не меняется.
- Новой migration нет.

Установка
=========

Если ZIP скачан в ~/Downloads, из корня проекта:

  unzip -o "$HOME/Downloads/sweet-run-task-hub-ui-stage4-20260930.zip" -d .

Затем:

  git status
  git diff --check
  git add -A
  git commit -m "Improve game task hub UI"
  git push origin main
  ./update.sh
