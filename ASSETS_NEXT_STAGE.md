# Следующий этап: декорации и ассеты (НЕ входят в этот патч)

Цель текущего патча — включить server-authoritative тип награды `world_decor` на существующих объектах категории `decor` прежде, чем загружать новый арт.

## Как готовить новые декорации

- Каждая новая декорация должна иметь **уникальный стабильный `id`**, `category:'decor'`, размер `w × h` по изометрической сетке и корректный шаблон размещения.
- Отдельный высококачественный изометрический ассет в стилистике «Мира Зеффи» (кремовый, розовый, золото, мягкие формы), **без массивного основания** и с прозрачностью там, где нужна. Для поворачиваемых объектов — все необходимые ракурсы с согласованной точкой привязки; при строительстве — отдельные этапы, если они предусмотрены.
- Включить ассеты в существующие `assets/mir_zeffi`, sprite manifests / asset checks и каталожные определения; **не создавать дубль движка рендера**.
- После добавления объекта в `world/catalog.js` с разрешённой категорией и без `retired` он сможет попасть в белый список наград, но сначала нужно проверить корректность sprite manifest и client/Worker parity.
- Для уникальных сезонных наград стоит отдельно продумать `giftOnly`, тематические названия, уникальные изображения награды, коллекционные карточки и правила повторной выдачи. В текущем allowlist `giftOnly` намеренно исключён: нельзя включать непроверенный эксклюзивный объект одним флагом.

## Возможные первые сезонные наборы

«Цветущий Зеффи» (цветочное дерево, арка, клумба, фонтан); «Кофейная улица» (кофейная вывеска, столик, стойка цветов); «Праздник сердец» (розовое сердце, романтический фонарик, украшенный фонтан).

Никаких новых изображений в этом патче **нет**. Следующий архив с картинками должен содержать **отдельные PNG/WebP для каждого элемента**, структуру, размеры/привязки и отдельный готовый промт интеграции для Codex, в соответствии с рабочим регламентом.
