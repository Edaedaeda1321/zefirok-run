# Сладкий Забег — коллекционный декор и «Книга развития города»

**Компактный ZIP-патч для существующего production-проекта.** Исходная рабочая точка: свежая ветка `main` репозитория `Edaedaeda1321/zefirok-run` на момент подготовки (16.10.2026). В архиве — только добавленные и изменённые файлы с исходными путями. Полной папки `assets` нет.

## Что добавлено

1. **Control Center → Сезонный пропуск → редактор награды.** Новый вариант «🌷 Декор Мира Зеффи». Показывает лишь 16 существующих и не списанных из каталога объектов категории `decor`. Ни здания, ни парки, ни дороги, ни пешеходные покрытия нельзя выдать как декор. Количество: 1–20 шт. Существующая таблица Season Pass продолжает использовать совместимый `reward_type='points'` с серверным префиксом `item_id='world_decor:<id>'`, без изменений старого CHECK.
2. **Control Center → сезонные кейсы.** Разрешено добавлять те же декорации в пул с весами выпадения (группа «Коллекционные предметы»), количеством 1–20. В отличие от уникальной косметики, повторный декор накапливается и не конвертируется в очки. Старые кейсы шести постоянных категорий **не изменены**; добавление декора в них — отдельный будущий этап, требующий отдельной интеграции с их системой наград.
3. **D1-учёт прав на декор.** Уникальные receipts выдачи, общие для Season Pass, сезонных кейсов и глав города; материальный подсчёт количества; защита от повторных выдач. Серверный `place-gift` ставит только наградный декор, сверяет число полученных и уже созданных экземпляров в *одной D1-транзакции*, не трогая кошелёк. Перемещение, склад и восстановление существующих подарочных экземпляров работают через штатные операции города.
4. **Пять долгосрочных глав «Книги развития города».** «Уютный городок», «Кофейная столица», «Легендарный Мир Зеффи», «Цветущий район» и «Город мечты Зеффи». Последние две продолжают цели после 10 уровня. Сервер проверяет жителей, уют, парки, магазины, дороги и разнообразие декора. Награда за главу: **один конкретный существующий декор**. Прогресс и подтверждение награды — только Worker+D1; специального требования к платным/случайным предметам нет.
5. **UI игрока.** Главы находятся внутри раскрываемой панели «Город и цели»; полученный декор находится в стандартном складе и отмечен 🎁. Состояние приходит в существующем запросе `/api/world/state` и ответах существующих операций; дополнительного startup-запроса не добавлено.
6. **Тесты.** Семь новых SQLite-тестов на allowlist, восстановление сохранений, одноразовые receipts, проверку открытия глав и недоступность наград по обходным путям. Встроены в штатный production gate.

## Обязательно: новая миграция перед включением Worker

`migrations/0123_zeffi_world_decor_and_chapters.sql` — добавочная, не удаляет и не переименовывает существующие таблицы. Создаёт четыре отдельные таблицы с наградным декором и главами. **Сначала применить миграцию на production D1, затем запускать `./update.sh`.** Миграция не применяется автоматически простым `git push`.

Работать из корня **проверенной актуальной локальной копии `main`**; перед распаковкой убедиться, что не осталось незакоммиченных сторонних изменений. Рекомендуемый порядок:

```bash
# Распаковать архив, сохранив вложенные пути, в корень репозитория.
git status
git diff --check
npm run check:fast

git add -A
git commit -m "Add World decor rewards and permanent city chapters"
git push origin main

# С применённым патчем и той же конфигурацией Wrangler:
npx --yes wrangler@4.131.1 d1 migrations apply zefirok-rewards --remote

# Стандартный production-flow проекта; НЕ запускать вручную отдельный wrangler deploy.
./update.sh
```

До применения миграции нельзя выпускать игрокам новый тип награды/кейс с декором: выдачи завершаются ошибкой (fail closed); уже существующие награды и города сохраняются.

## Как настраивать в CC

- **Сезонный пропуск:** открой награду нужного уровня и лейна → выбери «Декор Мира Зеффи» → выбери доступный предмет → введи количество (1–20) → проверь предпросмотр → сохрани. Выбрать парковую постройку или здание нельзя ни на клиенте, ни на сервере.
- **Сезонный кейс:** выбери/создай кейс → отметь нужные позиции «Декор Мира Зеффи», настрой количество и вес → выставь шансы групп так, чтобы сумма была 100% и у каждой группы с ненулевым шансом были предметы → сохрани. Для декора повтор всегда увеличивает запас.
- **Игрок:** после server-authoritative выдачи откроет личный Мир Зеффи (если доступ разрешён), зайдёт в «Склад», увидит подарочную карточку, установит свободный экземпляр; уже установленный можно убрать и вернуть без новой выдачи.
- **Книга:** раскрой в городе «Город и цели», проверь прогресс, нажми «Забрать» у завершённой главы; Worker перепроверит состояние и запишет одноразовую выдачу.

## Границы и безопасность

- В выпущенных **обычных шести видах кейсов** новый тип пока не подключён: здесь поддерживаются *сезонные* кейсы, управляемые через сезонный пропуск. Не подменяйте таблицы обычных кейсов вручную.
- Списания/начисления очков, кофе и зефира остаются в прежних server-authoritative потоках. Декор в Season Pass не увеличивает очки, хотя использует совместимый `reward_type='points'` во внутреннем формате.
- Если «Мир Зеффи» ограничен allowlist тестеров, награду можно получить из пропуска, но **разместить её смогут только игроки с разрешённым доступом к городу**.
- Новый декор пока использует **нейтральную штатную иконку** в наградных карточках. Новый набор картинок и отдельные сезонные редкости не включены: см. `ASSETS_NEXT_STAGE.md`.
- Проведены статическая проверка синтаксиса, 7 SQLite-тестов и полный локальный `npm run check:fast` (**84 проверочных этапа**, D1 интеграция **явно пропущена**). Production D1 миграция, интеграция в реальном Telegram и live-деплой здесь **не запускались**.
- Для отката не удаляйте новые D1-таблицы/receipts: в них могут находиться законно выданные игрокам награды. Сначала отключите новые слоты наград и откатите только код после проверки совместимости.
