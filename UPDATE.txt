Сладкий Забег 1.0.8 — Profile / Rating server-timeout hotfix
Дата: 2026-08-18

Что исправлено

1. Убран тяжёлый cold-start Season Pass на каждом новом Worker isolate
- ensureSeasonPassSchema больше не запускает полный CREATE/PRAGMA/seed/rebalance только потому, что поднялся новый isolate.
- Добавлен persistent schema-ready marker в bot_system_state.
- Если marker ещё не создан, выполняется быстрый read-only контроль существующих таблиц и обязательных колонок.
- Полная старая подготовка схемы запускается только если структура действительно неполная.
- После полноценной подготовки версия схемы помечается готовой.

2. Чтение рейтинга больше не пишет сезон в D1
- /api/leaderboard/state использует read-only выбор текущего/будущего/завершённого сезона по времени.
- Старый ensureSeason с UPSERT/reconcile остаётся для инициализации пустой базы и серверных процессов, но не выполняется на обычном открытии рейтинга.
- Будущий сезон для карточки определяется read-only по времени, а не только по уже обновлённому status.

3. Сокращена задержка формирования рейтинга
- Независимые D1-чтения top / игрока / награды / следующего сезона запускаются параллельно.
- Расчёт места и Season Pass tier остаётся тем же по смыслу.

4. Убраны дубли запросов при открытии профиля
- Одновременные refreshLeaderboard для одного игрока и режима теперь склеиваются в один in-flight request.
- Повторный ответ Telegram больше не запускает принудительно второй такой же запрос рейтинга.
- requestTelegramProfile не повторяется на каждом открытии профиля, если актуальные Telegram-данные уже получены.
- Полный startup package после Telegram profile throttled до одного раза в 60 секунд для того же пользователя.
- Если профиль открыт, запрос рейтинга стартует раньше фонового startup/retry.

5. Фоновая повторная отправка завершённого забега больше не пугает игрока ложным таймаутом
- Автоматический retry pending run работает тихо.
- Он больше не блокирует загрузку рейтинга ожиданием своего ответа.
- Явная отправка результата после реального забега по-прежнему показывает обычные success/error сообщения.

Не менялось
- баланс зефира/кофе/очков;
- начисление XP и наград;
- логика рейтинговых очков, мест и сезонной награды;
- Story Visual для зефира/кофе;
- Season Pass контент;
- Control Center / Test Project;
- Staging / Promote;
- UI-порядок блоков профиля.

Изменённые файлы
- index.html
- src/worker.js

D1 migration
- Отдельная команда миграции не требуется.
- Первый Worker после деплоя сам создаёт лёгкий schema-ready marker; существующие данные игроков не переписываются.
