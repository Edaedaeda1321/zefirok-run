ЧТО ИСПРАВЛЕНО

1. Физические покупки: стабильный requestId при повторе после сетевого таймаута
- requestId физической покупки сохраняется локально и повторно используется после закрытия окна, перезагрузки или потерянного ответа.
- новый requestId не создаётся при обычном retry одной и той же операции.
- идентификатор очищается только после подтверждённого успешного ответа.
- та же защита синхронизирована со старым profile.html.

2. Flash Offer: списание валюты и выдача наград сделаны атомарными
- списание баланса больше не выполняется отдельной операцией перед выдачей.
- проверка баланса, списание, виртуальные награды, кейсы, бустеры, физические коды и перевод покупки в completed входят в один D1 batch.
- если любая операция внутри batch падает, изменения не должны остаться частично применёнными.
- убран опасный ручной refund после частично завершённой покупки.
- requestId Flash Offer также сохраняется между сетевыми повторами.
- добавлена очистка зависших предварительных резервов Flash Offer.

3. Покупка обычного кейса
- НЕ ПЕРЕПИСЫВАЛАСЬ: проверка показала, что текущая реализация уже списывает баланс и создаёт granted_cases в одном D1 batch.
- заявленная ошибка «кейс создан до списания» в текущем коде отсутствует.

4. Промокоды: атомарное погашение и восстановление после повтора
- запись redemption, увеличение redemption_count и создание всех записей reward_delivery_queue теперь фиксируются одной D1 batch-операцией.
- при ошибке внутри этой операции не должно оставаться частично погашенного промокода.
- повтор для уже существующего redemption восстанавливает недостающие элементы очереди по сохранённому snapshot наград вместо безусловного отказа «уже использован».
- ID элементов очереди детерминированы, что защищает от дублирования при восстановлении.

5. Ограниченный stock магазина: закрыто crash-window между reservation и decrement
- создание shop_stock_consumptions и уменьшение остатка связаны SQLite-триггером в рамках одной операции INSERT.
- повтор одного и того же consumptionId не уменьшает остаток повторно.
- при нулевом остатке вставка откатывается.
- освобождение reservation возвращает ровно одну единицу только если строка reservation действительно была удалена.

6. Floating UI: локальный runtime больше не отсутствует
- добавлены локальные floating-ui.core.umd.min.js и floating-ui.dom.umd.min.js.
- локальный runtime реализует используемый проектом набор API: computePosition, autoUpdate, offset, flip, shift, size.
- существующий CDN fallback в HTML сохранён как резерв.
- deploy asset-check теперь проверяет наличие и требуемый API этих файлов, а не только news manifest.

7. Автокомпенсация релиза 1.0.6 больше не запускается из обычного API игрока
- ensureRelease106PlayerFix убран из общего пользовательского request path.
- проверка/применение перенесены в системный scheduled/cron flow.
- массовые выдачи и запись marker теперь объединены в один D1 batch, чтобы marker не расходился с результатом массовой операции.

8. /api/bot/health больше не раскрывает Telegram webhook-диагностику и не вызывает Telegram API
- публичный endpoint возвращает только минимальный статус сервиса.
- URL webhook, pending updates, last error и другие эксплуатационные детали наружу не выдаются.

9. Сезонные напоминания: увеличена пропускная способность
- batch подготовки уведомлений увеличен с прежних 20 игроков до 80/120 в зависимости от окна напоминания.
- общий notification queue также получил увеличенный batch.
- существующие quiet-hours, ограничения частоты и пользовательские notification policy сохранены.

10. /api/admin/health больше не публикует карту внутренних API
- публичный health возвращает только минимальный статус и версию.

11. Статические assets: технические файлы исключены из публикации
- добавлен .assetsignore для src/, migrations/, scripts/, wrangler.jsonc, update.sh, package-файлов, архивов и служебных файлов.
- дополнительно Worker возвращает 404 на технические пути до ASSETS fallback.
- публичные игровые HTML и обычные assets не блокируются.
