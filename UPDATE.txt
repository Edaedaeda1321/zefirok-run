Сладкий Забег — Critical Performance 1.2
Дата: 15.08.2026

ЧТО ИСПРАВЛЕНО

1. Жёсткие тайм-ауты пользовательских API
- Кейсы, награды, рейтинг, синхронизация профиля, покупки/акции и общие игровые запросы больше не могут бесконечно держать интерфейс в состоянии «Открываем… / Загружаем…».
- При проблеме сети управление возвращается игроку, а существующие idempotency/run guards защищают повторные операции.
- В сезонном пропуске обычные запросы и access-check ограничены 7 секундами вместо 20/16 секунд.
- Telegram initData для пропуска передаётся из родительской Mini App сразу; короткий polling остаётся только fallback.

2. Startup и чтение кейсов больше не ждут очередь старых наград
- Обработка pending reward delivery вынесена из критического пути startup и /api/cases/state.
- Очередь продолжает обрабатываться в background/waitUntil; существующий cron остаётся резервным механизмом доставки.
- Чтение состояния игры больше не превращается в скрытый job-runner.

3. Убраны повторные тяжёлые пересборки профиля
- Один и тот же authoritative profile переиспользуется внутри одного read/run request.
- Для настоящих admin write/set сохранён отдельный post-write authoritative fold, поэтому старые правила pending grants/overrides не изменены.
- Экономика и authoritative state остаются серверными.

4. Maintenance cache
- Состояние техработ кешируется в памяти Worker на 2 секунды и coalesces параллельные cold reads.
- Любое изменение из бота, Control Center, restore snapshot или release flow немедленно инвалидирует кеш.
- Это убирает лишний D1 SELECT почти перед каждым игровым API, не делая переключатели техработ «запаздывающими» надолго.

5. Инкрементальные задания сезонного пропуска
- Добавлена таблица season_pass_task_progress.
- Забеги / очки / зефир / кофе / открытые кейсы теперь обновляют дневные и недельные счётчики инкрементально вместо SUM/COUNT всей истории на каждом событии.
- Прогресс события фиксируется вместе с серверным settlement/opening, где это возможно.
- Для сезонного кейса используется authoritative MAX-reconciliation, чтобы исключить двойной счёт при гонке lazy backfill.
- Background reconciliation восстанавливает редкий пропущенный event и никогда не уменьшает уже накопленный прогресс.

6. Выполнение задания и уведомления стали событийными
- При переходе через target сервер сразу создаёт точную запись выполненного задания.
- В Fast Settlement выполненное задание возвращается клиенту в том же ответе, поэтому игрок видит его сразу.
- Обычные и подарочные кейсы также возвращают task notice прямо в ответе открытия — дополнительный сетевой refresh для нового API не нужен.
- Telegram Bot API не находится на критическом пути: отправка идёт в background.
- Перед Telegram-отправкой сервер повторно проверяет, не забран ли уже XP; если забран — сообщение не отправляется.
- Старого тяжёлого full task reconciliation после каждого события больше нет.

7. Ошибка/тайм-аут открытия кейса больше не запускает второй блокирующий запрос
- Интерфейс освобождается сразу.
- Восстановительная loadCaseState синхронизация запускается в фоне.

ЧТО НЕ ИЗМЕНЕНО
- proof/checkpoint chain забега;
- серверные лимиты античита;
- run-session и защита от повторного settlement;
- idempotency/guard-механизмы покупок и кейсов;
- формулы начисления очков, зефира, кофе, profile XP и Battle Pass XP;
- баланс наград, цены, шансы кейсов и физические награды;
- существующие данные игроков и уже полученные награды.
