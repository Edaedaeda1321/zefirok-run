# Мир Зеффи — Общий город: серверная сюжетная прогрессия (закрытый RC)

Источник изменений: актуальная production-ветка «Сладкого Забега» с патчами закрытого RC, UI каталога и интерактивного обучения. Патч предназначен для интеграции в существующую структуру, а не для переписывания игры.

## Система

Добавлены три таблицы в СУЩЕСТВУЮЩУЮ D1 `zefirok-rewards` (миграция `0118_zeffi_story_progression.sql`):

- `zeffi_story_players`: текущая глава (0–3), версия изменения и битовая маска открытых сюжетных районов. `unlocked_mask`: бит 1 = Дом фестивалей, бит 2 = «Белый Кролик». Состояния проверяются на согласованность; недостоверные данные закрываются по принципу fail-closed.
- `zeffi_story_visits`: посещённые места по подписанному Telegram ID, без дублей.
- `zeffi_story_events`: доступность серверных событий `garden` и `festival`. Завершение мероприятия определяется ТОЛЬКО суммой общего фонда `zeffi_community_projects` из миграции 0115, не client-side счётчиком.

Маршрут: `POST /api/world/story/progress`, операции `state`, `visit`, `advance`. Сервер берёт Telegram ID из подписанного `initData` и проверяет `WORLD_ENABLED`, `WORLD_TESTER_IDS`, `WORLD_STORY_ENABLED`. Клиент не может задавать себе главу, уровень, статус события, район или вознаграждение. `advance` использует optimistic revision и повторную SQL-проверку требований главы. Нет нового кошелька, валютных списаний, наград, изменения личного района и дополнительных D1.

## Первые три главы

1. **«Первые прогулки»**: площадь, кафе «Зефирок», Белкино → открывается район Дома фестивалей.
2. **«Вместе строим город»**: квартал друзей, станция, Сад встреч + завершённый серверный общий сбор `garden` → открывается сюжет «Белого Кролика».
3. **«Праздник Зеффи»**: Дом фестивалей, «Белый Кролик» + завершённый серверный общий сбор `festival` → текущая история пройдена.

Неизвестный район остаётся закрытым. Внесение личного вклада НЕ обязательно. Завершённые совместные события видны всем разрешённым игрокам, а личные посещения и главы уникальны для игрока. Игрокам с уже существующим личным городом не требуется ничего переносить; новый сюжет стартует с первой главы, без сброса города/валюты.

## Клиент

«История» / «Районы» показывает текущую главу, цели, прогресс двух общих событий, открытые и закрытые зоны. Открытие главы разрешает только серверное состояние. Открытие места регистрирует посещение. Кнопки «Обновить историю и события» и «Завершить главу и открыть район» используют signed API. При ошибке D1 серверная история не заменяется локальной песочницей. Старый автономный предпросмотр остаётся только локальным.

Запрос состояния истории добавляется только при первом входе в Общий город; последующие запросы — на посещение, завершение главы или явное обновление/возвращение приложения, без polling в каждом кадре. Существующая очередь общих взносов, баланс очков и строительство сохраняются.

## Перед развёртыванием

1. Проверьте рабочую ветку и не перезаписывайте несохранённые правки (особенно из исправлений рейтинга, RC и обучения).
2. Убедитесь, что миграции `0114_zeffi_world.sql`, `0115_zeffi_community_fund.sql`, `0117_zeffi_world_tutorial.sql` применены. Примените новую `0118_zeffi_story_progression.sql` к основной удалённой D1 ДО публикации Worker. Не выполняйте миграцию вручную через произвольные SQL-запросы.
3. Запустите локальные проверки и просмотр `git diff --cached`. Выполните `git push origin main`, затем `./update.sh` как штатный деплой. НЕ использовать `npx wrangler deploy` напрямую.
4. Оставьте существующий список `WORLD_TESTER_IDS`, проверьте `WORLD_ENABLED=true` и `WORLD_STORY_ENABLED=true` для закрытого RC. В режиме аварийного отключения все входы должны отказать без обращения к D1.
5. Проверьте на двух разрешённых Telegram-аккаунтах и одном постороннем. Первый открывает главы последовательно; второй получает общие события, но не чужие посещения. Посторонний не должен видеть ни карту, ни серверную историю.

## QA после публикации

- Проверить связку: глава 1 → посещения → подтверждение → новая зона. Кнопка закрыта до выполнения целей.
- В главе 2 завершение сбора на Сад встреч должно быть глобальным и не должно требовать личного вклада; то же для Дома фестивалей на главе 3.
- Закрытые зоны не открываются по прямому URL, при повторном / поддельном запросе или при устаревшей revision.
- Перезапустить Telegram: посещения, глава и открытые районы должны сохраниться. Проверить на другом устройстве тем же аккаунтом.
- Проверить старых пользователей, сохранения личного района, его покупки/таймеры, баланс очков, фонд и обучение.
- Если фонд ещё не собран — сюжет корректно ждёт общего результата; НЕ менять суммы фондов вручную для обхода условия на production.
- Проверить поведение при отсутствии сети/ошибке D1: экран сообщает о сбое, локально районы не открываются.

## Ограничения RC

Это серверный каркас из трёх первых сюжетных глав с целями и двумя общественными событиями. Новые главы, персонажные диалоги, сцены, награды и live-редактор событий в этом патче не добавлены. Не представлять его как завершённую сюжетную кампанию. Интеграционные проверки запущены на локальном SQLite с симуляцией D1; удалённая D1 и реальная доставка/поведение в Telegram после публикации требуют отдельного smoke-теста.
