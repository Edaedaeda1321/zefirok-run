Sweet Run — Unicode sound filename fix v3
Base: main commit 5943da6ff41dc275126af14951233443f7603605

WHY DEPLOY FAILED
Two MP3 files exist in Git but their names contain the accented character "é" (Café).
On macOS the visible filename can be stored/exposed in decomposed Unicode form (NFD), while the path literal parsed from src/worker.js is composed (NFC). The two strings look identical but are not byte-for-byte identical. The strict preflight therefore correctly stops the deploy. This same class of mismatch can also produce a real static-asset 404.

FIX
1. Rename the two deploy-addressed MP3s to ASCII-only filenames without changing their bytes:
   assets/sounds/moon_marshmallow_cafe_epic.mp3
     -> assets/sounds/moon_marshmallow_cafe_epic.mp3
   assets/sounds/moon_marshmallow_cafe_2_epic.mp3
     -> assets/sounds/moon_marshmallow_cafe_2_epic.mp3
2. Update every textual reference to the old filenames.
3. src/worker.js in this patch already uses the new paths.
4. check-live-content-assets.mjs now explains Unicode-normalization mismatches instead of reporting them only as generic missing files. It still FAILS the build; no CRITICAL check is weakened.

HOW TO APPLY IN THE REAL REPO
Overlay src/ and scripts/ from this archive onto the repository, then from repo root run:

  node scripts/rename-unicode-sound-files.mjs
  node scripts/check-live-content-assets.mjs
  git status
  git diff --check
  git add -A
  git commit -m "Normalize live content sound paths"
  git push origin main
  npx wrangler deploy

IMPORTANT
Do not delete/re-encode/re-export the MP3 files. The migration script renames the existing files in-place and handles macOS NFC/NFD spelling by enumerating the directory first.
