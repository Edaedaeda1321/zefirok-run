# Сладкий Забег — Seasonal Case Info Hotfix v1

База патча:
- актуальная ветка `main`, проверенная на коммите `3ed9dba799396cdde9793ec78ea5dc522fdec024`;
- `battle-pass.html` сохраняет уже внесённые исправления Season 2 и текущую анимацию открытия сезонного кейса;
- `src/worker.js` сохраняет предыдущую поддержку выдачи сезонных кейсов из Player Operations / Компенсаций.

## Что изменено

### Сезонный кейс теперь открывает информацию как обычные кейсы
Нажатие на верхнюю часть карточки сезонного кейса больше не является «пустым» действием. Открывается отдельное окно с двумя вкладками:

1. `Содержимое`
   - арт и название конкретного сезонного кейса;
   - сезон и количество кейсов на аккаунте;
   - количество наград за одно открытие;
   - все ресурсы, обычные кейсы, косметика и прочие награды из фактического пула;
   - каждая награда открывается отдельно с шансом и правилом получения.

2. `Шансы и правила`
   - фактический шанс каждой группы: ресурсы / косметика / постоянные кейсы;
   - фактический шанс каждой награды внутри группы;
   - правила нескольких слотов;
   - правила дубликатов и компенсации;
   - пояснение серверного открытия.

Кнопка `Открыть кейс` на карточке по-прежнему сразу запускает открытие. В информационном окне также есть кнопка открытия/проверки текущей операции.

## Откуда берутся шансы

Клиент больше не пытается угадывать состав сезонного кейса по картинке или названию.
Worker передаёт конфигурацию именно того экземпляра кейса, который будет открыт следующим:

- `snapshot_json` выданного кейса имеет приоритет;
- используются `slots`, `duplicatePoints`, `groupChances` и список наград с их `weight`;
- если старый выданный кейс не содержит snapshot-пула, используется текущая серверная конфигурация как fallback.

Это важно для архивных кейсов: если после выдачи владелец изменил будущую конфигурацию сезона, игрок видит правила своего уже выданного кейса, а не случайно новую таблицу.

### Формула совпадает с серверным открытием
Если заданы проценты групп, сервер:
1. выбирает доступную группу по `groupChances`;
2. внутри выбранной группы выбирает награду по её `weight`.

Интерфейс считает проценты по той же схеме. Если настроенная группа пуста, проценты нормализуются между реально доступными группами — так же, как при серверном выборе.

Если кейс выдаёт 2–5 наград, в интерфейсе показывается точный шанс позиции **для первого слота**. После каждого выпадения выбранная позиция удаляется из пула текущего открытия, поэтому шанс следующего слота пересчитывается. Это явно написано игроку, чтобы не показывать ложный общий процент.

## Повторы
Косметика не исключается из первоначального выбора только потому, что уже принадлежит игроку. Если сервер выбирает уже имеющийся предмет, он заменяется на `duplicatePoints` из конфигурации этого сезонного кейса. Информационное окно показывает именно это правило.
