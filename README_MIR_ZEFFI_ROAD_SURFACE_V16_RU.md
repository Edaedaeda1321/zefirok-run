# Мир Зеффи — дороги на одной поверхности, v16

## Что исправлено

Старый рендерер рисовал `world_road_mask_XX.webp` для **каждой** клетки Road.
Но каждый такой WebP уже содержит плитки/подиум **соседних** клеток.
На поворотах, Т-образных развилках и перекрестках геометрия многократно накладывалась: появлялись «ступеньки», двойные торцы, разная высота полотна, а здания рядом с дорогой визуально стояли на борту другой плитки.

Новый рендерер строит дорожную полосу как **одно связное покрытие в плоскости земли**:
- каждая клетка отрисовывается однажды;
- каждая связь между соседними клетками — однажды;
- дорога, повороты, Т-перекрестки и крестовины объединяются без накладывания объемных спрайтов;
- используются пастельная светлая брусчатка, розовые декоративные плитки и небольшой нижний контактный край (3 пикселя);
- полотно немного уже полной клетки: у оснований соседних домов сохраняется полоска травы;
- защищенные стартовые дорожные клетки имеют небольшой золотой знак;
- маршруты пешеходов по Road, уже купленные клетки, сохранения и цены не меняются.

**Компромисс дизайна:** новый способ рисования слегка меняет рисунок дорожного полотна, так как повторяемые объемные `world_road_mask_*` не годятся для бесшовной геометрии. Исходные ассеты не удаляются. Если позже потребуется точная текстура старой брусчатки, ее можно подготовить отдельно как **плоскую** текстуру дороги, не возвращая индивидуальные подиумы.

## Состав
- `patches/mir_zeffi_roads_v16.patch` — точечная правка `world/renderer.js` (не замена целого старого файла).
- `world/tests/road-surface-v16.test.mjs` — пять регрессионных тестов дорожной топологии.
- `scripts/check-world-road-surface-v16.mjs` — быстрая проверка прямой, угла, Т-перекрестка, 4-стороннего перекрестка и одиночной клетки.

## Применение

Сначала убедиться, что предыдущие изменения в Git сохранены, а архив скачан в `~/Downloads/`.
Запустить в **корне** репозитория `zefirok-run`:

```bash
 git status --short
 git switch main
 git pull --ff-only origin main
 unzip -o "$HOME/Downloads/Mir_Zeffi_Roads_Solid_Ground_v16_patch.zip" -d .
 git apply --check patches/mir_zeffi_roads_v16.patch
 git apply patches/mir_zeffi_roads_v16.patch
 node --check world/renderer.js
 node scripts/check-world-road-surface-v16.mjs
 node --test world/tests/*.test.mjs
 node --no-warnings --experimental-sqlite scripts/check-zeffi-world-integration.mjs
 node scripts/check-production-gate.mjs
 git diff --check
```

Если `git apply --check` не проходит, **не использовать `git apply --reject` или принудительную замену целого файла**. Сверить текущий файл с патчем и исправить конфликт отдельно. Если тесты не прошли, остановиться до отправки в GitHub.

После проверок:

```bash
 rm -f patches/mir_zeffi_roads_v16.patch
 git add world/renderer.js world/tests/road-surface-v16.test.mjs scripts/check-world-road-surface-v16.mjs README_MIR_ZEFFI_ROAD_SURFACE_V16_RU.md
 git diff --cached --check
 git diff --cached --stat
 git commit -m "fix(world): render connected roads as one ground surface"
 git push origin main
 ./update.sh
```

## Проверка

1. Открыть автономный `Mir_Zeffi_Roads_Solid_Ground_v16_OFFLINE.html` из отдельного архива.
2. Проверить прямую линию, поворот на 90 градусов, Т-перекресток и пересечение четырех направлений.
3. Разместить дома вплотную к дороге; проверить, что пешеходы остаются на дорожной поверхности.
4. Проверить дороги при увеличении/отдалении камеры и на iPhone в Telegram.
5. Убедиться, что покупка/удаление Road списывает только ожидаемую сумму через действующий Worker.

Локально проверено: тесты топологии 5/5, контроль пяти схем дорожной сети, браузерная сцена с двумя домами, площадкой, NPC и Т-образным перекрестком без ошибок JavaScript; при плотной сети ~441 клетка отрисовка на тестовом Chromium занимала около 29–54 мс на кадр (не показатель скорости iPhone). **Полный production gate и реальный Telegram на телефоне нужно прогнать в исходном репозитории.**

Модули Worker/D1, логика покупки дорог, API, сохранения, строительство зданий, NPC и экономический баланс этим патчем не меняются.
